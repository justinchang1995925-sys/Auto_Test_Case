# Auto Test Case Skill

`Auto Test Case Skill` 是一个面向高质量测试设计的 Skill 项目，用于根据多源输入文档自动生成
测试点思维导图、测试用例主表、评审追溯附表与质量审计报告。

该项目当前核心 Skill 为 `req-testcase-generator`，适用于测试工程师、测试负责人，
以及需要参与测试评审的产品和研发同学。Cursor 与 Claude Code 共用同一份 Skill（见「目录结构」）。

## 项目目标

将分散的需求信息、技术方案、UI 设计和交互说明统一纳入测试设计流程，输出：

- 需求原子化清单（REQ，含可测性与覆盖状态）
- 六维度测试点思维导图
- 异常交叉适用性矩阵（通用异常事件 × 阶段原型）
- 测试执行主表 + 评审追溯附表 + 追溯矩阵
- 专项测试用例表 + 专项数据采集表（多次采样统计类指标）
- 测试计划
- 质量审计报告（四报告 + 硬门禁）

项目默认仅支持高质量模式，所有输入均按统一高标准执行，不区分快速模式或草稿模式。

## 支持的输入

### 1. 文档内容类型

- 需求文档（PRD / BRD）
- 技术方案文档
- UI 设计文档
- 交互文档

### 2. 文档载体格式

- 飞书文档链接
- PDF
- Word（`.docx` / `.doc`）
- TXT / Markdown
- 直接粘贴到对话中的正文

## 输出内容

### 1. 测试点思维导图

基于六个维度生成测试点，TP 编号前缀与维度绑定：

| 维度 | TP 前缀 |
|------|--------|
| 功能 | `TP-F` |
| 性能 | `TP-P` |
| 稳定性 | `TP-S` |
| 兼容性 | `TP-C` |
| 安全 | `TP-SEC`（`001~099` 信息安全 / `101~199` 功能安全） |
| 用户体验 | `TP-UX` |

交付为 Draw.io（`.drawio`）文件，可直接导入飞书云文档。

### 2. 测试用例主表

用于测试执行，固定字段如下：

| 用例序号 | 优先级（P0-P3） | 测试标题 | 测试类型 | 前置条件 | 操作步骤 | 预期结果 | 测试结果（PASS/FAIL） | 备注 |
|---------|----------------|---------|---------|---------|---------|---------|---------------------|------|

操作步骤与预期结果必须逐条一一对应、条数相等（构建期强制校验）。

### 3. 评审追溯表（含风险评估）

用于评审追溯和风险讨论，字段如下：

| 关联需求/方案条目 | 关联测试点 | 用例序号 | 设计技法 | 测试数据 | 风险等级 | 风险评估依据 | 优先级评估 | 用例状态 | 解除条件 | 备注 |
|-----------------|-----------|---------|---------|---------|---------|-------------|-----------|---------|---------|-----|

`用例状态` 仅允许 Ready / Blocked / Draft，是可执行性报告的唯一计数来源。

Excel 类交付件统一汇入**一个工作簿多 Sheet**，文件名 `测试交付件-{需求名}-{日期}.xlsx`。

## 核心流程

```text
Phase 0    文档摄入（需求 / 技术方案 / UI / 交互）
Phase 1    需求分析 + 待确认问题清单（A-G 七组固定模板）
Phase 1.5  需求原子化清单（REQ）+ 文档章节反查对账
Phase 2    测试点思维导图（六维度）+ 异常交叉适用性矩阵
Phase 3    测试用例主表 + 附表 + 追溯矩阵 + 测试计划
Phase 4    质量审计（四报告 + 硬门禁）
```

每阶段结束需用户确认后再继续。完整架构与流程图见 `REQ-TESTCASE-SKILL-ARCHITECTURE.md`。

## 质量机制

- **风险驱动优先级**：P0-P3 与风险等级联动（高↔P0/P1，中↔P2，低↔P3）
- **主表 + 附表双输出**：兼顾执行与评审
- **反模式库**：禁止模糊、不可判定、不可执行的用例写法
- **审计三铁律**：禁止裸报零、违例必列 ID、交付前贴自查回执
- **10 项硬门禁**：全部由脚本遍历数据算出，不靠肉眼核对
- **覆盖深度最低标准**：功能类 REQ 须各自含正向 + 非正向；专项 REQ 须配套功能可用性用例；
  功能安全类 REQ 须含触发 + 恢复且多触发源各 ≥1 条

### 反模式示例

以下写法会被视为低质量用例并要求改写：

- 预期写“显示正常”
- 一步骤验证 3 件事
- 前置条件写“系统正常”
- 操作步骤写“按要求操作”
- 用例标题只是功能名
- 步骤 5 条对应预期 3 条

## 目录结构

Skill 采用**单一真源 + junction** 布局：`.agents/skills/` 是唯一一份真实内容，
`.cursor/`、`.claude/` 及用户级目录均为 junction 指向它，任一处编辑都直接落到真源。

```text
.
├── README.md
├── REQ-TESTCASE-SKILL-ARCHITECTURE.md
├── skills-lock.json                     # 27 个 lark-* skill 的来源存档
├── .agents/skills/                      # ← 真源（唯一真实内容）
│   ├── req-testcase-generator/
│   │   ├── SKILL.md                     # 流程与门禁规范（主文件）
│   │   ├── templates.md                 # 输出模板与维度检查清单
│   │   ├── exception-library.md          # 通用异常注入库（EX）与交叉选点规则
│   │   ├── doc-ingest.md                # 文档摄入说明
│   │   ├── pipeline.md                  # 交付件构建管道用法与易错点
│   │   └── scripts/
│   │       ├── tcgen/                   # 构建层+同步层，照搬不改
│   │       └── project_template/         # 项目侧模板，复制后只改数据层
│   └── lark-*/                          # 27 个飞书 skill
├── .cursor/skills/  → junction 至 .agents/skills/（Cursor 编辑入口）
└── .claude/skills/  → junction 至 .agents/skills/（Claude Code 加载）
```

用户级 `%USERPROFILE%\.claude\skills\` 同样 junction 至真源，
因此**任何目录下的新项目都能用到最新 Skill**。

## 使用方式

提供文档并发出类似指令：

- `分析需求`
- `问题已确认：...`
- `确认 REQ 清单`
- `生成测试点`
- `测试点已确认`
- `生成主表和附表`
- `生成质量审计报告`

示例：

```text
根据这份 PRD 和技术方案，生成测试点和测试用例
```

```text
这是 UI 稿和交互说明，请补充体验与兼容性用例
```

```text
测试点已确认，输出主表和附表，并附风险依据
```

### 交付件落地（Phase 3/4）

交付件由 Skill 自带管道生成，**禁止现场重写**建表、审计运算、思维导图与飞书同步代码：

```bash
cp <skill>/scripts/project_template/*.py ./   # 1. 复制模板到项目目录
# 2. 只改数据层 reqs.py / cases_*.py / d_ex_*.py / spec.py，与 build.py 顶部 CONFIG
python build.py                                # 3. 产出 xlsx + drawio，并打印硬门禁结论
python sync_feishu.py all                      # 4. 飞书格式与饼图重建（先回填 sheet_id）
```

## 关键文件说明

| 文件 | 内容 |
|------|------|
| `SKILL.md` | Skill 主流程、编号体系、交付物规范、各 Phase 规则、审计三铁律与硬门禁 |
| `templates.md` | 输出模板、字段校验规则、风险规则、反模式库、审计口径说明 |
| `exception-library.md` | 通用异常事件（EX）定义、阶段原型（ST）、交叉选点规则 |
| `doc-ingest.md` | 输入文档摄入说明 |
| `pipeline.md` | 交付件构建管道分层、快速开始、模块职责、易错点 |
| `REQ-TESTCASE-SKILL-ARCHITECTURE.md` | 架构设计、流程图、输出规范、使用说明总览 |
